# 05 - INS reference table (Codex CXG 36-1989): provenance, counts, checks. STATUS: NOT RELEASED (licence unresolved)

The derived table lives in data/pending/ins_reference.csv. It is NOT in src/foodscan/resources/, so no release or web build
contains it (the loader and scripts/web_tables.py read it only if it is placed in resources/ deliberately).
It is display data only. It never feeds ins_map.csv, a marker, or a NOVA decision, and it does not state what a code does
in any scanned food: the source itself says a single additive "can often be used for a range of technological purposes"
and that the manufacturer declares the most descriptive class; "Inclusion in the INS does not imply approval by Codex".

## Counting policy and reconciliation (one policy: one row per distinct INS identifier as printed)
Identifiers counted as printed: plain (457), letter-suffix such as 150a (46) and sub-codes such as 500(i) (171) = 674 rows
in the numerical list (Section 3), of which 50 are bold group headings with no functional class (e.g. 500, 501, 451, 161h).
- Numerical list: 674 rows. Alphabetical list (Section 4): 679 rows.
- Matching rows: 669. Only in numerical: 5 (161h, 161h(i), 161h(ii), 557, 650: all real, verified on the rendered pages).
  Only in alphabetical: 10 (106, 108, 112, 114, 116, 118, 126, 128, 136, 138): these are NOT additives, they are even
  printed page numbers read as codes, so the alphabetical list has 669 real rows.
- Earlier figures: "669" was the matching count; "608 complete + 58 partial = 666 included + 18 withheld = 684" mixed
  group headings, page-number artefacts and one-list-only rows. Reconciled, nothing dropped to force a total:
  684 raw = 674 real rows + 10 page-number artefacts; 674 = 624 leaf entries kept + 50 group headings.
- Current build (data/pending): 624 entries = 562 where both text readings agree + 51 partial (classes both readings agree on;
  not checked visually; the source may list more) + 11 checked against the rendered PDF (list in
  data/pending/ins_reference_visual_checks.csv, with page numbers and reasons).
- Aliases/ranges: the source prints optional parenthetical synonyms (e.g. "Natamycin (Pimaricin)"); they are part of the
  name, not separate rows. There are no code ranges in the lists. No duplicate identifiers occur within a list.

## What the checks do and do not show
- Agreement between the numerical and alphabetical readings is an extraction-consistency check on the same PDF, not
  independent corroboration of the science. The visual checks compare the extraction with the rendered page images.
- NOT done: a visual check of the 51 partial rows. They stay marked "partial". No missing class was invented.
