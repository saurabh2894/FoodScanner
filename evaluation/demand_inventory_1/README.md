# Demand inventory 1: every unassessed term in the evaluation evidence

Generated by `scripts/mine_unassessed.py` (read-only tooling, zero classification change) on build 3df79d7 (main after PR #3). Re-generate with `python scripts/mine_unassessed.py --force`.

Files: `inventory.csv` (one row per normalised term) and `inventory.json` (same rows, lists kept as lists).

## Evidence streams (kept apart)
- **paste_live**: every `evaluation/*/inputs/*.txt` analysed now with this build. Clean text, current vocabulary.
- **paste_recorded**: `unassessed` lists recorded in evaluation JSON artifacts (paste results, flip-check before/after files). Clean text, older builds.
- **photo_recorded**: "NOT ASSESSED" blocks in recorded photo and browser results. OCR-damaged text: a term seen ONLY here is `photo_only` (probably OCR damage, not a vocabulary gap) and never ranks as demand.

## Columns
`rank_open` (rank among open terms), `term` (lowercase, brackets and percentages removed), `distinct_paste_inputs` (distinct input IDs across the two paste streams: the ranking key), `live_inputs`, `live_mentions`,
`recorded_paste_mentions`, `photo_mentions`, `photo_only`, `noise` (stray fragments such as `631`, `quot`), `recognised_now` (this build recognises it: a closed gap, kept visible), `input_ids`, `raw_variants`, `sources`.
Input IDs: `b1/N05` (fresh batch 1), `b2`, `b3`, `neg` (negation addendum), `dev15` (dev regression). A `?<file>` ID marks a photo result that is not one of the corpus inputs (for example the millet-puff fixture).

## Limits
- The corpus is the 66 frozen inputs plus their recorded results: the same labels the vocabulary was drawn from. This inventory ranks demand in THOSE labels; it does not measure generalisation.
- Terms are grouped by a simple normalisation (no stemming, no synonym merging): "iodized salt" and "iodised salt" would be separate rows if both were unrecognised.
- Whether a term may become a lexicon row is decided elsewhere (source clause, kind, condition). Demand alone never adds a row.
